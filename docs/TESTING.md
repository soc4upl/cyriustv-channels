# Проверки проекта

Без изменения сервера:

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q src deploy scripts legacy
node --check src/panel/static/app.js
python3 deploy/install.py --config deploy/settings.example.json --check
```

Для тестов backend нужен Flask/Werkzeug, для оформления Pillow; для проверки
воспроизведения нужен FFmpeg/ffprobe. На Ubuntu подходят пакеты из `INSTALL.md`.
Без этих зависимостей соответствующие тесты помечаются skipped, а не passed.

Тесты создают собственные временные базы, пользователей и ключи. Они не используют
рабочие учётные записи, сессии, видео, TLS и конфиги установленной панели.

Проверяются:

* вход, отсутствие доступа без пароля, CSRF, Origin и блокировка торрент-операций;
* конфигурация одного и двух дисков, отделение источника от панели;
* отклонение некорректных доменов, URL и сетевых правил;
* защищённые внутренние HLS-маршруты и ограниченное sudo-правило;
* последовательная/случайная очередь, подтверждение и устаревание команд;
* запуск HLS на двух синтетических файлах, смена фильма и отклонение внешнего пути;
* генерация ЕПГ с адресом нового источника.

Подготовка проекта не является фактическим развёртыванием на второй чистой машине.
`--apply`, Certbot/DNS, systemd после перезагрузки и показ через конкретный Flussonic
окончательно проверяются при установке на целевой сервер.

## Проверено при подготовке переноса

2026-10-29: все 12 тестов прошли на macOS и Ubuntu 24.04. На Ubuntu отдельно
успешно проверены `nginx -t` для изолированных HTTP-конфигов и `systemd-analyze verify`
для служб. Минимальная серверная сборка FFmpeg без lavfi использовала собственный
синтетический образец через `CYRIUS_TEST_SAMPLE`; файлы медиатеки не читались.

Чистая установка ОС, выпуск нового сертификата и переключение CDN в эти тесты
не входили. Рабочий сервер при подготовке репозитория не обновлялся.
