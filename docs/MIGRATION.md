# Перенос с действующего сервера

## 1. Поднимите новый сервер отдельно

Установите проект по `INSTALL.md` с новым временным доменом панели. Не запускайте
`--apply` на действующем сервере: установщик предназначен для чистой машины.
До завершения проверки старый сервер продолжает эфир.

GitHub хранит код, оформление и шаблоны. Фильмы, рабочие настройки и резервные
копии из него не восстанавливаются: они переносятся отдельно **между серверами**.
Скачивание медиатеки на Mac для переноса не требуется.

## 2. Перенесите медиа

Используйте rsync/SFTP по SSH непосредственно с сервера на сервер. Начните
с одного тематического каталога и проверьте права и свободное место.
Пример выполняется на новом сервере, с вашим SSH-доступом к старому:

```bash
sudo rsync -a --info=progress2 OLD_USER@OLD_HOST:/srv/cyrius/disk2/media/KidsHD/ /srv/cyrius/media/KidsHD/
sudo chown -R ffpu:cyrius-media /srv/cyrius/media/KidsHD
```

Удалённый пользователь должен иметь право чтения. При необходимости организуйте
отдельный временный доступ на старой машине. Не подставляйте пароль в команду.
Не используйте `--delete` и не отключайте проверку SSH host key.

При двух дисках копируйте каждый **физический каталог** отдельно. Не копируйте
одновременно `/srv/cyrius/disk2/media/` и его bind-представление `media/*/Disk2`,
иначе получите дубли. Карантин и незавершённые загрузки не добавляйте в медиатеку.

## 3. Перенесите нужные настройки

Сначала сохраните новые настройки на новом сервере. Затем выборочно перенесите:

* русские названия из `/etc/cyrius/movie-titles-ru.json`;
* исключения из `/etc/cyrius/media-exclusions.json`;
* пользовательские логотипы и параметры оформления;
* очереди `/var/lib/cyrius-control/<номер>/queue.json`, только если пути совпадают.

Не заменяйте новый `copy-channels.json` целиком старым: там могут быть прежние
URL, пути и служебные поля. Объедините только нужные настройки каналов.
Новые домен, HTTPS, `runtime.env`, доступ CDN и настройки дисков должны остаться
от новой установки.

`state.json`, кеши, временные HLS, `command.json` и `ack.json` переносить не надо.
Фильм на новом сервере запускается с начала или выбирается через панель.
Пользователей и пароли безопаснее создать заново, сертификат выпустить заново.
Настройки Transmission и торрент-источников переносить не требуется.

## 4. Проверьте новый эфир

1. Запустите один канал, проверьте видео, звук, название и логотип.
2. Проверьте источник с машины Flussonic и в IPTV-приложении.
3. Проверьте смену двух фильмов и обновление ЕПГ.
4. Запустите оставшиеся каналы по одному и оцените CPU.
5. Только после этого поменяйте источники во Flussonic на новый IP.

Flussonic не обновляется скриптами этого репозитория. Доступ и лицензия на CDN
проверяются отдельно.

## 5. Переключение и возврат

Старый сервер сохраняйте до подтверждения стабильного показа на новом.
Для возврата достаточно вернуть прежние HLS-источники в Flussonic.
Отключение старого сервера и удаление файлов — отдельное решение владельца.

Резервную копию рабочей базы, секретов и конфигов храните вне Git, с доступом
только администратора. Если независимые диски используются без RAID, они
увеличивают доступный объём, но не создают автоматического зеркала фильмов.
